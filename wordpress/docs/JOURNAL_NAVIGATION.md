# Навигация журнала

## Заголовок и метки над обложкой

Основной journal title: «Автоматизация бизнеса, CRM, сайты и ИИ — журнал Сутри»; видимый h1: «Автоматизация бизнеса». Подборки имеют тематический title, пагинация сохраняет номер страницы. Open Graph получает тот же title через штатный `wp_get_document_title()`.

`sy3_article_tags()` выводит кликабельные собственные `post_tag`, а если они не назначены — фактические рубрики статьи. У 11 публичных статей сейчас нет post_tag, поэтому отображаются рубрики. Это не автоматическое создание тегов: taxonomy, assignments и тела статей не меняются. В main-site карточках метки входят в media wrapper перед обложкой, прежний дублирующий eyebrow в тексте скрыт. На странице статьи метки стоят перед cover. Личный сайт и карточки кейсов/услуг исключены. Native tag archives используют шапку журнала и обычную выборку WordPress.

Проверены title/OG/h1, все метки над картинками при 320/390/1440, клавиатурный переход в рубрику, home/category/search/pagination/cases, FAQ+два CTA внутри статьи. В read-only fixture проверены приоритет настоящих тегов, escaping, category fallback и personal/case exclusion; настоящих tag archive для HTTP canary пока нет. Evidence: private/journal-title-tags-preview.json. Theme 1.4.6; deployment и live evidence фиксируются в PR и private/journal-title-tags-*.json.

На основном сайте шапка журнала разделяет описание, поиск и темы. Поиск — нативный GET WordPress с `post_type=post`; выбранная тема сохраняется при поиске и его сбросе. Переключение темы сохраняет поисковую строку, но начинает выдачу с первой страницы.

`inc/journal.php` объединяет редакционные категории в широкие темы только для навигации и main query журнала. В частности, ИИ и ИИ-шлюз входят в одну подборку. Старые category URL сохраняют исходную выборку. Назначения категорий, тела статей, статусы, редакционные часы и личный сайт не изменяются. Новые категории нужно включать в соответствующую группу явно; все публичные статьи доступны через «Все статьи» независимо от группировки.

Счётчики показывают число разных опубликованных непарольных статей во всей теме, а строка результата — размер текущей выборки с учётом поиска. Пустые темы скрыты, кроме явно выбранной. Черновики не попадают ни в выдачу, ни в счётчики. Неверный/массивный `journal_topic` безопасно выбирает все статьи. Никакого JavaScript для поиска или фильтров не требуется.

Проверка: 320/390/768/1440 px без overflow, поле и кнопка 48 px, поле 16 px, клавиатурный focus/Enter; выбор ИИ, поиск CRM внутри темы, сброс/переключение темы, пустая/некорректная тема, спецсимволы, native CRM category, вторая страница и архив кейсов. Preview содержит 10 публичных статей, production — 11: ИИ-шлюз в preview остался черновиком. Независимое review и live evidence фиксируются в PR и private/journal-*.json. Новые backups не создаются.
