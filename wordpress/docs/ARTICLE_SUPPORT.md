# FAQ и промежуточные CTA журнала

Theme 1.4.4 добавляет два компактных CTA между завершёнными разделами длинной статьи и FAQ в конце. В начале текста есть ссылка к вопросам. Обе CTA ведут в существующие Telegram/MAX support inbox; звонки, новые формы и новые получатели не добавляются. У примера `crm-est-zayavki-teryayutsya` первая вставка стоит после диагностической таблицы, вторая — после разбора повторных обращений. У остальных материалов позиции выбираются после двух разделов и примерно на 70% разделов; внутрь таблиц, списков, code/pre и групп ничего не вставляется.

`theme/inc/article-support-copy.json` содержит 55 индивидуальных вопросов/ответов и 22 CTA для 11 опубликованных статей. Ответы основаны на их собственных проверках и процессах; вымышленных результатов и обещаний бесплатной работы нет. Reviewed copy привязан к SHA256 исходного body. Preview hash принимается только при `SY3_PREVIEW` и non-production. После редактирования статьи устаревший copy отключается до повторной проверки и обновления hash.

Для остальных 300 черновиков и будущих материалов краткие ответы извлекаются из собственных разделов: вопрос из заголовка или понятного типа раздела, ответ — законченные предложения исходного абзаца. Это вспомогательное представление существующего текста, не дополнительный факт или новая кейсовая история. До снятия редакционной паузы их FAQ/CTA также нужно проверить; для индивидуальной редакторской версии добавить slug с `faq`, двумя `ctas` (`title/text/label`) и `body_hash`. JSON не управляет URL. Автоматического обещания поисковых rich results или отдельной FAQPage-разметки нет.

Рендерер `theme/inc/article-support.php` работает перед `do_blocks` только для main singular `post` в главном цикле. Он не изменяет `post_content`, статусы, даты, seed/review hashes, расписания и метаданные. Admin, REST, RSS, AJAX, парольные статьи, страницы, услуги, архивы и личный сайт исключены. Собственный FAQ редактора сохраняется; обычный details с примером не блокирует FAQ. Повторный вызов не дублирует компоненты. Для коротких материалов с менее четырьмя подходящими разделами вставки не навязываются.

Проверка без записей:

```sh
HTTPS=on SERVER_PORT=443 wp --path=/var/www/sy3-wordpress --allow-root eval-file wordpress/tools/check-article-support.php
```

Проверяется реальный корпус из 311 материалов: две вставки между полными блоками, один FAQ, соответствие copy текущему body опубликованных статей, отсутствие дублей, парольная защита, сохранение существующего FAQ и fingerprint posts/postmeta. Preview содержит 10 публичных статей и gateway в draft; production — 11 публичных. Браузерный smoke проверяет полный `the_content`, клавиатуру, bot links, ширины 320/390/768/1440, исключения home/archive/service/feed/REST и ошибки загрузки. Private evidence: `article-support-{preview,live}-checks.json` и `article-support-rollout.json` в существующем private каталоге проекта. HTTPS smoke через loopback не заменяет внешнюю проверку достижимости.

Публиковать только reviewed head: новые два файла в theme/inc и изменения functions.php/direction.css/style.css. Плагин контента, статьи и базы не переимпортировать. Исходное состояние theme 1.4.3 восстановимо из принятого Git; новых backups не создавать. Web-form sender, bot services и editorial timer этим изменением не активируются и не перезапускаются.
