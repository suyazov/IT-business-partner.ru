# Дополнительные изображения кейсов

`content/case-galleries.json` описывает 66 отобранных изображений для 24 существующих кейсов. Файлы находятся в `content/media/case-galleries/`; SHA256 в manifest относится к точным WebP. Использованы существующие материалы портфолио, без генерации интерфейсов и показателей заказчиков. Обложки сохранены.

После вступительного абзаца добавляется компактный блок «Проект в деталях»: до трёх превью с подписями и штатным WordPress lightbox. На телефоне изображения идут одной колонкой. В редакторе это обычные Group → Heading/Gallery → Image, файлы зарегистрированы в медиатеке и доступны для дальнейшей правки. Изображения целиком помещаются в превью, без обрезания скриншотов; полная версия открывается по нажатию.

Материалы сверены с исходными проектами и визуально проверены. Кадры с CRM-записями, частной перепиской и неподтверждёнными результатами исключены. У учебного примера Битрикс24 сохранено указание демонстрационного формата; историческая платёжная страница не обозначает актуальный тариф. У AVG показаны исходный сайт и задачи DNS/HTTPS, без утверждения о завершённом исправлении.

Три кейса сохраняют существующий набор: аналитика найма уже содержит три снимка интерфейса с демонстрационными данными; HR-ТЗ — свою схему; для антиспама не найдены надёжные дополнительные оригиналы. Общие имена старых blob-файлов у антиспама указывали на другие проекты, поэтому эти изображения не использованы.

## Импорт

`wp --allow-root --path=/var/www/sy3-wordpress eval-file <checkout>/wordpress/tools/import-case-galleries.php` по умолчанию только проверяет исходники и конфликты 24 целевых case bodies с принятой редакцией `editorial/BATCH_INDEX.json`. Существующие изменения редактора не заменяются.

Для записи требуются отдельная production-authority, три общих project locks, чистый reviewed exact head, root-only независимый receipt с SHA256 manifest, `SY3_GALLERIES_APPLY=1` и `SY3_GALLERIES_LOCK_PID`. Команду выполнять с `--user=artem_admin`. Точные опубликованные media bytes проверяются до регистрации, metadata — против manifest. Детерминированные имена позволяют повторить незавершённый импорт, не создавая новые attachment при каждом запуске.

Каждый case body обновляется отдельной InnoDB-транзакцией с CAS и read-back. Сохраняются прежний текст, остальные поля, даты и metadata; добавляются только галерея и два служебных meta-маркера. При повторном apply проверяются также существующие файлы/attachment/metadata, а не только маркер. Статьи, их очереди, обложки, теги и второй сайт не меняются.

Нативная JS-валидация Gutenberg 7.1.3 проверила все 24 галереи и 66 Image-блоков; удаление вставленного gallery block возвращает исходный case body байт в байт. Независимый review и live-проверка являются отдельными шагами после commit.

Оригиналы и служебный manifest визуальной проверки не публикуются. Временные исходники после read-back удаляются только под storage lock; уникальные источники, доступы, базы, Git и receipts сохраняются. Новых резервных копий нет.
