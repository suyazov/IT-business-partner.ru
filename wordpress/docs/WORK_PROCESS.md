# Текст о способе работы

Первый экран страницы представляет услуги и опыт вместо перечня возможных ролей. В «Стилсофт» указано руководство внедрением финансового/складского учёта, документооборота и отчётности; в CoreApp — руководство разработкой образовательной платформы для ФИНАМ. Основание: записи 185-2026-10-21-hh-yarkiy-kadr-head-it-infrastructure.md и 108-2026-10-06-hh-it-project-manager-online-school.md в registries/applications/records/2026 репозитория suyazov/affine-pages-backup. Не заявляются личное программирование 1С, разработка всей платформы CoreApp или неподтверждённые метрики.

Редакторский приём — ресурсный подход из glvrdru/HOW_TO_WRITE_2018_RESOURCE_FIRST_SEO_PROMO_2026-10-21.md в suyazov/course-knowledge-base: подтверждённая работа → факт для покупателя. Это применение исследованного метода своими словами.

В блоке «Избранные проекты» показаны три разные компетенции по опубликованным кейсам из cases.json: hiring-funnel-dashboard — разработка аналитики найма внутри Битрикс24; glosscheck — ИИ-приложение с файлами, OCR, историей и лимитами; stilspace — интеграция готовой вёрстки с 1С-Битрикс для спутникового оператора. Это выбор для знакомства с опытом, а не рейтинг всех работ. Текст не приписывает дизайн СТИЛСПЭЙС, создание спутников, сокращение сроков найма или экономию на ИИ. Закрытый клиент найма не называется.

Текущий tools/update-about-experience.php применяет эту подборку только к body ID5/about: точные before/after hashes, CAS, InnoDB, сверка всех прочих полей и metadata. Старый seed hash сохраняется без изменений. Переимпорт страницы и изменение редакционных подтверждений не выполняются.

Страница `/about/` описывает шесть конкретных действий владельца: обсуждение задачи с заказчиком и пользователями, разбор существующих систем, требования и ТЗ, показ будущего решения, организация разработки и проверка результата. Отдельно объясняются артефакты, самостоятельная реализация, работа с подрядчиками и применение ИИ.

Основа — ограниченная проверка рабочих материалов владельца в GitHub: описание ролей, шаблоны заявки и технической декомпозиции, реестр и конкретный подготовленный пакет требований. Это подтверждает содержание аналитической работы; подготовленное ТЗ не называется внедрённой функцией. Частные названия, сотрудники, номера задач, ссылки, бюджеты и данные систем в публичный текст и этот репозиторий не перенесены. Подробная карта доказательств находится только в `private/work-process-facts.json` на сервере. Свежий live CRM-аудит в этом этапе не проводился.

Дополнительная публичная фактура: собственная разработка подтверждается согласованными кейсами LibertyGas, СТИЛСПЭЙС и «Читай-ка» из `content/cases.json`; передача инструкции — LibertyGas, контроль формы и CRM — Маткласс. Подрядчики по 1С/BI и применение ИИ прямо описаны владельцем в этой задаче. Прототип представлен как возможный способ согласовать новый интерфейс, без утверждения о завершённом клиентском внедрении. Нет обещаний фиксированных сроков, гарантированного роста продаж или личного выполнения всей технической работы в командных проектах.

`content/work-process.php` собирает нативные Gutenberg blocks; `content/pages.php` использует его только для expertise-варианта. Личная версия и остальные страницы сохраняются. `tools/update-work-process.php` ограничен production/preview identity, owned page ID5/slugabout и двумя полями: `post_content`, `_sy3_seed_hash`. У него exact before/after hashes, InnoDB, row locks, два prepared CAS UPDATE в общей транзакции, read-back полей/metadata; неизвестные ручные правки сохраняются. Повторный запуск ничего не пишет.

```sh
HTTPS=on SERVER_PORT=443 SY3_ALLOW_PRODUCTION_IMPORT=1 SY3_IMPORT_DRY_RUN=1 wp --path=/var/www/sy3-wordpress --allow-root eval-file wordpress/tools/update-work-process.php
```

Исходный production body восстановим из принятого Git `2ce59ef` при expertise/HTTPS context; совпадение factory/body/seed SHA256 подтверждено до правки. Новых backups не создаётся. Preview прошёл применение и повтор, Chrome DevTools a11y/DOM проверку при 320/390/1440 px без overflow, неработающих изображений и console errors. Production preflight не пишет; применение только после exact-head review. Delivery и live evidence — в PR и `private/work-process-{rollout,live-checks}.json`.
