Проверено 23.10.2026. Это локальная проверка кандидатов, production не публиковался. Сравнения текста — PILOT_COMMERCIAL.md и PILOT_ARTICLES.md, версии и hashes — соответствующие manifest.

## Что прошло

- PHP lint изменённых фабрик и read-only renderer; JSON parse; `git diff --check`.
- Read-only инвентаризация 360 объектов, identity/body hashes/dates и source mapping; фактические 334 alt обложек и два меню захвачены отдельно. Сканер не редактирует тексты и не обращается к сети/WordPress.
- Первые 10 кандидатов прошли Chrome DevTools на 320/390/768/1440 px. После расширения трёх статей повторены именно их 12 сочетаний в отдельном локальном Chromium через CDP: по одному H1, без горизонтального выхода, обрезанных заголовков и неработающих изображений. Для lazy images дожидались `decode()`. Семь коммерческих тел не менялись.
- Главная содержит 7 FAQ; каждая расширенная статья — 4 FAQ и 2 промежуточных CTA, построенных текущей темой из нового текста. Старые curated FAQ/CTA не перепривязаны к новым hashes без редакционной приёмки.
- Нативный `wp.blocks.parse()` после регистрации core blocks: 574 блока в десяти текущих кандидатах, invalid/missing — 0. Проверена реальная библиотека текущего WordPress.
- Повторный вызов действующего `sy3_editorial_quality()`: CRM — 11 421, sitemap — 11 170, backup — 11 030 содержательных знаков; таблица и схема присутствуют, complete=true. Gate не ослаблен.
- Таблица, process-map и блок источников трёх статей сохранены побайтно; SVG/CSV не изменены. Значимые ссылки сохранены, кроме осознанной замены старого личного Telegram на support bots; добавлен подтверждённый кейс Маткласса.

## Как устроен preview

Приватный loopback router подставляет кандидат в PHP-объект записи только на время запроса, затем использует существующий шаблон темы. Импорт в WordPress не запускался, статусы черновиков не менялись. Первые восемь проверок двух draft не прошли из-за пустого query fixture; после исправления только router fixture все восемь повторены успешно. Тела/даты/ID/metadata production этим не затрагиваются.

Существующий локальный leads plugin подменяет часть CTA на тестовую форму; это отличие стенда от production. В candidate HTML прямые support bot URLs сохранены, форма не публикуется и отправка не проверяется. Навигация и динамические карточки отражают существующий preview-корпус, а не новую миграцию production.

Нативный валидатор загрузил wp-preferences, который без авторизации получил ожидаемый GET `users/me` HTTP401. При повторном CDP-прогоне отложенный ответ этого запроса попал также в последнюю запись HTTP-журнала. Это запрос валидатора, не invalid block и не отказ загрузки публичной страницы; для него не создавали сессию и не ослабляли доступ. В article-template исключений JavaScript нет. DevTools MCP при повторной проверке сообщил о занятом профиле; использован собственный изолированный Chromium. Общий серверный браузер, его cookies и кабинеты не изменялись.

Evidence вне webroot: `private/editorial-refactor-20261023/expanded-pilot-preview.json`. Исторический короткий пилот — `preview-checks.json`; его прежние 515 блоков не относятся к новым body hashes.
