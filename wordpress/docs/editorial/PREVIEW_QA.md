- Нативный `wp.blocks.parse()` после регистрации core blocks: 515 блоков в десяти кандидатах, invalid/missing — 0. Проверена реальная библиотека текущего WordPress.

## Как устроен preview

Приватный loopback router подставляет кандидат в PHP-объект записи только на время запроса, затем использует существующий шаблон темы. Импорт в WordPress не запускался, статусы черновиков не менялись. Первые восемь проверок двух draft не прошли из-за пустого query fixture; после исправления только router fixture все восемь повторены успешно. Тела/даты/ID/metadata production этим не затрагиваются.

Существующий локальный leads plugin подменяет часть CTA на тестовую форму; это отличие стенда от production. В candidate HTML прямые support bot URLs сохранены, форма не публикуется и отправка не проверяется. Навигация и динамические карточки отражают существующий preview-корпус, а не новую миграцию production.

Нативный валидатор на отдельной локальной странице загрузил wp-preferences, который без авторизации получил ожидаемый GET `users/me` HTTP401. Это побочный запрос harness, не invalid block и не ошибка публичного шаблона; для него не создавали сессию и не ослабляли доступ. В проверенных публичных article-template страницах console errors отсутствовали. Общий серверный браузер, его cookies и кабинеты не изменялись.
