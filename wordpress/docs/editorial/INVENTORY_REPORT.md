# Инвентаризация sy3.ru: редакционный baseline

Дата: 23.10.2026. Исходный Git head: `ca7ae08f26bafd5228c250fb4ff7e08a3c925284`.
Охват: только sy3.ru. Это результат read-only инвентаризации, не заявление о завершённой редактуре сайта.

## Что учтено

| Тип | Publish | Draft | Всего |
|---|---:|---:|---:|
| Страницы | 5 | 1 | 6 |
| Услуги | 16 | 0 | 16 |
| Кейсы | 27 | 0 | 27 |
| Статьи | 11 | 300 | 311 |
| **Объекты WordPress** | **59** | **301** | **360** |

У каждой записи сохранены ID, URL, slug, статус, локальные/GMT даты создания и изменения, SHA256 body и привязка к исходнику. CSV содержит **3070 строк поверхностей**, а не 3070 страниц: body/title/excerpt/meta-description/SEO-title/link labels, дополнительные FAQ/CTA/alt/query, 26 отдельных групп интерфейсного текста.

Baseline SHA256: `0d68d6544efd1bdb3ed0a4e801b3b9f329277674f2726ec7b09c5f8c6a62e50b`. Сам baseline и полные тексты из него в Git не копировались. У всех 360 body SHA256 проверен по захваченному содержимому. Координатор дополнил исходный read-only срез обложками и текущими меню; body/hash/status/dates исходных записей сохранены.

**359/360** объектов имеют проверенное сопоставление с существующими файлами: 58 по seed/slug, 301 по editorial key/slug. №3 `privacy-policy` — непубличный стандартный черновик WordPress, repo-источник не найден; это отмечено `RUNTIME_ONLY_DEFAULT_WORDPRESS`, а не придуманный путь. Для главной/страниц сверены фабрики и фактические include; журнал создаёт `tools/import-content.php`, его экран выводит тема.

Состав источников статей: 10 начальных записей из `content/articles.json`; 100 из `editorial/calendar.json` с проверкой конкретного `@@ id|slug` в пакетном файле; 101 из `search-content/manifest.json`; 100 из `beget-content/manifest.json`. У первых 110 учтены **дополнения**, а не замена оригинала: `longform/manifest.json` и существующий `longform/articles/<file>`. Поэтому один файл не выдаётся за полный текущий body. 16 услуг сопоставлены с 4 + 10 + 2 определениями в трёх JSON; 27 кейсов — с `content/cases.json`.

Сопоставление доказывает identity и существование исходника. **Равенство генератора текущим ручным блокам не заявляется**; для будущей записи нужен отдельный hash-concurrency dry-run. В CSV включён явный read-only overlay пилота: у **10 body rows** поле `new_version` указывает на полный candidate (JSON Pointer на `commercial.json` либо отдельный HTML). Их исходные hashes/статусы/даты и остальные поверхности title/excerpt/meta сохранены из baseline.

Подготовлено **7 коммерческих текстов**: страницы №4/5/6, услуги №9/10/11 и кейс №21. Владелец принял тон, независимая проверка новых версий остаётся отдельным этапом. **3 расширенные статьи** №60/262/281 имеют 11 421 / 11 170 / 11 030 содержательных знаков и статус `LENGTH_REQUIREMENT_MET_NEEDS_EDITORIAL_REVIEW`. У всех десяти действие `REWRITE` означает подготовленный вариант, а не применённое изменение. Кандидатный hash и baseline identity проверены; редакторское утверждение не имитируется. **Остальные 350 объектов не включены в этот overlay**; следующие пакеты готовятся отдельно, их наличие не означает завершённую проверку всего корпуса.

## Частотность кандидатов

Таблица ниже считает только **body**: повторные представления FAQ, excerpt и SEO не суммируются с телом. Один объект может попасть в несколько строк. Это узкие механические сигналы `FLAGGED_CANDIDATE`, не оценка качества страницы или доказательство AI-происхождения.

| Код | Объектов body | Вхождений body | Что ещё нужно решить |
|---|---:|---:|---|
| AI_CLICHE | 19 | 19 | В основном оборот «не просто …, а …»; проверить, есть ли полезное противопоставление |
| BUREAUCRACY | 10 | 10 | Процессная формула вместо понятного действия; безопасность сохранять |
| JARGON | 146 | 326 | Проверить аудиторию/объяснение термина; термин не считается дефектом автоматически |
| FACT_UNVERIFIED | 5 | 5 | Все пять оставшихся совпадений прочитаны в контексте; это отрицания/пример чужой ошибки, **не обещания** |
| SEO_FILLER | 1 | 1 | «важно отметить» — слабый сигнал, полезность всего абзаца ещё не проверена |
| DUPLICATE_INTENT | 0 | 0 | Ищется между объектами по query, см. ниже |
| CTA_UNCLEAR | 0 | 0 | Проверка коротких названий ссылок отдельно от абзацев |
| PRIVACY_CRITICAL | 0 | 0 | Нуль по узким маркерам; это не полная privacy/security проверка |

Хотя бы один body-кандидат найден у **170** объектов; у **190** узких совпадений нет. Это не означает, что 170 страниц плохие, а 190 приняты. До overlay линт предлагал **195 KEEP / 135 MOVE_TO_TECH / 30 REWRITE**; текущий CSV с десятью подготовленными вариантами содержит **188 KEEP / 134 MOVE_TO_TECH / 38 REWRITE**. Линт-частотность выше от этого не изменилась: она относится к baseline. Подготовленных полных текстов **10**, публикаций **0**. `KEEP` без смысловой проверки означает только «не менять по результату этого линта». `MOVE_TO_TECH` означает проверить, нужно ли объяснение/другая глубина подачи; автоматического перемещения нет.

В отдельных интерфейсных поверхностях найден **1 объект / 1 вхождение CTA_UNCLEAR**: карточка `Подробнее` в `theme/functions.php`. Контекст карточки может делать ссылку понятной, поэтому это кандидат для review, а не требование везде менять кнопку.

Есть **1 пара / 2 объекта / 2 query-вхождения DUPLICATE_INTENT**: услуга №253 `bitrix24-support` и статья №303 `soprovozhdenie-bitrix24-chto-vhodit` используют `сопровождение Битрикс24`. Совпадение query подтверждено; конкурирующий интент **не установлен**. Вероятное разделение — покупка сопровождения и инструкция по составу/приёмке работ; проверить содержание и перелинковку. Изменений URL/301/слияния нет. Узкое сравнение нормализованных заголовков не дало других пар; оно не исключает смысловых дублей.

Суммировать все 3070 строк как независимые ошибки нельзя: одна фраза может повторяться в body, FAQ и excerpt. Для полного поиска смысловых повторов нужна редакторская партия с чтением соседних текстов.

Пять контекстных исключений связаны с точными body hashes в скрипте. При другом hash исключение не действует. Это **5 проверенных фрагментов**, не 5 полностью проверенных статей и не 311 смысловых review. Слова «CRM», «данные», «согласовать» отдельно не помечаются.

## Поверхности и пробелы доказательств

* 360 строк title/H1, 360 excerpt и 360 meta-description; 360 SEO-title фиксируют входной title и отдельно оговаривают override/суффикс, а не изображают захват итогового HTML.
* 360 наборов ссылок, 319 наборов сохранённых контактных CTA, 213 primary-query из источников. Доступность URL и естественная доставка сообщений здесь не тестировались.
* FAQ из сохранённых `details` есть у 13 объектов. Отдельно учтены динамические FAQ/CTA темы, включая JSON для 11 публичных статей; их нет в исходном body. Нельзя по нулю `details` сделать вывод «в статье нет FAQ».
* Inline alt учтён у 5 объектов. Для **334 cover-alt** прочитан фактический `_wp_attachment_image_alt`, все 334 непустые; attachment ID сверён с `_thumbnail_id`, URL и caption захвачены read-only. У 26 записей обложки нет. Значение alt сохранено в соответствующей строке CSV. Содержательность подписи и соответствие изображению ещё требуют визуальной проверки. Пустой alt в декоративной карточке может быть корректен независимо от attachment alt.
* Навигация/подвал/реквизиты/404/пустой поиск/пагинация/страницы каталога/поиск журнала/заголовки/OG/schema/FAQ/CTA/анимация/формы и их состояния учтены отдельными UI rows. Для навигации захвачены **2 текущих меню / 5 пунктов**: основное и подвал. Их значения и общий hash взяты из runtime; `tools/import-content.php` указан только как seed reference. Остальные настройки сайта полностью не выгружены.
* Отдельного glossary в проверенных контентных/тематических исходниках не найдено; наличие определений внутри 311 текстов ещё не оценено. Не создавать новый раздел ради галочки.
* Знания о роли, правах на изображения, техническом результате, ценах и актуальности внешней документации **не выводятся из body**. По каждому материалу нужно пройти карту фактов, не считать опубликованную формулировку независимым подтверждением.

## Граница проверки и доставки

Этот скриптовый аудит не заменяет полный смысловой разбор; независимый reader test **NOT_RUN**. CSV связывает десять пилотных body, а следующие принятые source-пакеты перечислены в **BATCH_INDEX.json** с точным Git commit, identity и hashes. Редакторские решения по ним — в REPORT.md каждого пакета. Реестр не утверждает, что все остальные title/meta/UI поверхности уже оценены. Эта инвентаризация не измеряет трафик, заявки, доверие или продажи. Массовая запись в WordPress, запуск очередей, создание publisher reviewed hash и production writes не выполнялись. Оба инструмента не обращаются к API или базе WordPress.

Baseline: editorial pause `1`, обе часы `false`. Статусы/даты/ID/slug/body/meta не изменены. Сохранённый sender-код формы имеет собственную authority; наличие исходника не доказывает доставки. Согласно проектному контексту работают отдельные Telegram/MAX inbox; естественный visitor→owner→reply не был проверен этим этапом.

Личный сайт исключается по site/hostname при входе скрипта. Общие PHP-шаблоны дополнительно помечены `SHARED_TEMPLATE_GUARD_REQUIRED`: будущая текстовая правка должна сохранить личную ветку, а не полагаться только на отказ скрипта от чужого baseline.

Для воспроизведения CSV с overlay (переменная указывает на приватный read-only baseline):

```sh
python3 wordpress/tools/editorial_audit.py "$SY3_EDITORIAL_BASELINE" wordpress/docs/editorial --pilot-root wordpress/docs/editorial/pilot
```

Без `--pilot-root` скрипт делает исходную инвентаризацию без присвоения candidate/review pointers. Наличие overlay не даёт полномочий на импорт или публикацию. Пилотный голос принят, требование длины подтверждено владельцем; следующий шаг — независимая проверка расширенных версий и партии из `REWRITE_PLAN.md`.
