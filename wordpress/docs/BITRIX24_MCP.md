# Работа Codex с Битрикс24 SY3

Владелец 24.10.2026 поручил настроить постоянный рабочий способ чтения и редактирования собственного `https://sy3.bitrix24.ru/` через MCP. Используется официальный сервер `https://mcp.bitrix24.tech/mcp/`, Streamable HTTP, без стороннего посредника. В портале включён только параметр `enable_bitrix_internal_mcp_server`; ранее включённое подключение внешних сервисов к BitrixGPT сохранено. Платные подключения/подписки не оформлялись.

## Подключение на сервере

В `/root/.codex/config.toml` добавлен только `[mcp_servers.sy3-bitrix24]`. Токен вынесен в `/root/.config/client-access/sy3.ru/bitrix24-mcp.json`, root:root 0600, вне Git. Каталоги доступа закрыты 0700. Значение токена не помещать в config, документы, prompts или журналы. MCP-доступ отделён от `bitrix24-rest.json`, который используется действующим отправителем заявок; этот вебхук не менялся.

`http_headers_helper` вызывает `/usr/bin/python3 -B /root/.local/libexec/sy3-bitrix24-mcp-headers.py`. Исходник helper — [bitrix24-mcp-headers.py](../tools/bitrix24-mcp-headers.py); он проверяет владельца/права/тип файла, фиксированные сервер и портал, печатает JSON-заголовок только для MCP-клиента. Ошибка не раскрывает секрет. Проверки helper выполнять с захватом stdout, никогда не выводить его терминалу.

У сервера получено 106 инструментов; в Codex включены 33 для задач/чек-листов/анализа проектов, поиска исполнителя и CRM-воронок/стадий/создания сделок. Почта, приглашения, кадровые изменения и удаление в этот набор не включены. Наличие инструмента не является поручением менять данные: действия выполняются по запросу владельца, массовые изменения требуют точного списка и границ задачи.

Набор официального MCP пока не содержит точечного чтения/редактирования всех полей контактов и существующих сделок. Для таких задач остаётся действующий прямой REST-доступ с CRM scope; конкретные методы проверять по актуальной документации. Не подменять точечное действие массовым `move_deals_between_*` и не менять интеграцию приёма заявок ради ручной работы.

## Проверка

`initialize` подтвердил `bitrix-mcp` 1.30.0, протокол 2025-03-26. `tools/list` и чтение существующих воронок прошли; воронка8 «Квалификация» соответствует порталу SY3. `codex mcp get sy3-bitrix24 --json` подтвердил корректную конфигурацию, header helper и список 33 инструментов.

Через MCP создана только техническая задача6 на владельца1, затем изменены заголовок/описание и статус на `completed`. Обратный `get_task_by_id` подтвердил изменения и завершение, срок/сотрудники/проект не добавлялись. Результат update был дополнительно сверен чтением без повторного write. Клиентские сделки/контакты, боты, таймеры и WordPress этим этапом не менялись. Receipt — `private/bitrix24-mcp-setup-20261024.json`, вне Git.

Конфигурация действует для Codex на этом сервере. Текущий уже запущенный тред автоматически не получает новый каталог инструментов; после переподключения MCP или перезапуска Codex сервер будет доступен нативно. До этого те же MCP-запросы выполняются через защищённый HTTP-доступ с helper. Это не установка плагина в ChatGPT web или на другом компьютере.

## Срок и восстановление доступа

Выданный токен имеет `exp` 03.11.2026 18:12:35 МСК. Автоматическое продление не настроено и не обещается. При истечении/401 открыть авторизованный портал: Приложения → MCP-подключения → Получить токен подключения, заменить только canonical secret file, сохранив root0600, затем переподключить сервер и проверить чтение. Старые токены не архивировать. Пароль/CRM-вебхук для этого не менять. При неизвестном результате записи сначала читать созданный объект, не повторять POST вслепую.

Для отключения удалить только блок `mcp_servers.sy3-bitrix24` и отозвать соответствующий доступ в Битрикс24 Паспорт. Удаление доступа не отменяет созданные/изменённые объекты. Существующий приём заявок по REST работает независимо.
