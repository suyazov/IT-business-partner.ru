# Источник портфолио

Снимок: 22 октября 2026. Существующая база AFFiNE: docId `VsTiC7mEuWAHb_FoPYBoF`, databaseBlockId `HRktcMM9Qi`. База и 25 документов прочитаны через канонический stdio MCP `/usr/bin/affine-mcp`. AFFiNE не изменялся.

В базе 34 строки, у 25 включён Share. Только они включены в `content/cases.json`; `affineDocId` связывает каждый кейс с оригиналом. Для Маткласса внутри документа было отдельное ограничение: владелец в текущем чате подтвердил получение согласия клиента на публикацию. VIP26/Технодарк (Share=false), внутренний Bridge (Share отсутствует) и остальные неотмеченные строки в новый публичный каталог не включены.

Выбраны готовые клиентские разделы: контекст, задача, результат. Операторские статусы, внутренние пути, идентификаторы тестовых сделок, инструкции для Workzilla и сценарии генерации иллюстраций не переносятся. Два ранее подготовленных подробных разбора сохранены с границами доказанного результата. Для дверной компании отдельно сохранено ограничение по SMS, старым сделкам и внешней телефонии. Новая проверка клиентских систем и измерение бизнес-эффекта в этот этап не входят.

23 изображения взяты из native blob-хранилища AFFiNE, просмотрены и оптимизированы в WebP с сохранением пропорций. SHA-256 файлов указан в JSON. Импорт создаёт стандартные вложения WordPress; обложку можно поменять через медиатеку. Карточки показывают изображения полностью, без обрезания подготовленных надписей. Для ПроффСтрой использовано второе доступное изображение документа, поскольку первое не загрузилось.

Два исключения: `00-cover.png` в документе антиспама фактически возвращает изображение СТИЛСПЭЙС; его не используем. Обложки «Формулы лидов» не удалось получить из хранилища (503/504). Эти два кейса используют собственные схемы из темы. Исходные документы и blob-хранилище не исправлялись.

На sy3.ru размещаются полные тексты. Личный сайт показывает четыре выбранные работы на главной и 25 ссылок на странице портфолио; тексты кейсов между доменами не дублируются. Совпадающие старые `/portfolio/<slug>` перенаправляются на соответствующий кейс основного сайта.

Сохранённые исходники старых карточек и статей остаются в Git. Импортированные ранее архивные записи локального кандидата сохранены в черновиках. Это не удаляет публикации действующего сайта и не является разрешением на production.
