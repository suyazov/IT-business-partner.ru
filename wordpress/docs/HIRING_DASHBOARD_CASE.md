# Кейс «Воронка найма в Битрикс24»

Публичный slug `hiring-funnel-dashboard`, существующий case ID574. По ссылке владельца прочитаны исходники и инструкция именно «Воронки заказчика», а не другой HR/Power BI отчёт. Внутренние ссылки, имя клиента, номера CRM и приватная матрица доказательств остаются вне публичного payload.

## Подтверждённый состав

- Вкладка в карточке вакансии; сводка по связанным откликам.
- Текущие стадии и история прохождения с конверсией — разные режимы.
- Нажатие этапа, список откликов, пагинация, резюме и карточка CRM.
- Доли с явным основанием расчёта; переходы с учётом хронологии, повторы одного отклика не увеличивают число посещений.
- Связь с вакансией, серверная проверка чтения, ограничение доступа к резюме, учёт оргструктуры HR и поля заказчика.
- Локальные проверки расчётов, сохранённая сверка с CRM, проверенные пользовательские сеансы и инструкция сопровождения.

Нет утверждений о сроке закрытия вакансии, экономии, ROI, каналах привлечения, фильтрах по периоду, экспорте отчёта, AI-оценке кандидатов или дедупликации физических лиц между разными откликами. Использование Codex при разработке подтверждено самим владельцем. Старый источник принятого body воспроизводим из редакционного pilot; новая редакция хранится в cases.json.

## Изображения

Использованы исходные HTML/JS/CSS интерфейса. Для снимков только адрес чтения данных заменён локальным JSON. Отображение, расчёт и обработчики выбора этапов взяты из исходников. Полностью заменены записи, числа, должность, роли и дата. На каждом снимке видна подпись «Демонстрационные данные»; captions поясняют, что числа не относятся к клиенту. Это снимки исходного интерфейса на демонстрационном наборе, не снимки действующей клиентской базы.

Обзор — `content/media/hiring-dashboard-overview.webp`, создаётся одна штатная media attachment с alt/caption и назначается обложкой ID574. Два состояния интерфейса — `theme/assets/hiring-dashboard-current.webp` и `hiring-dashboard-stage.webp`, используются внутри текста. Старые SVG и чужие вложения не удаляются.

## Scope и проверка

`sy3_sections` получает опциональные нативные table/buttons. При отсутствии этих ключей результат остальных кейсов не меняется. Новый case содержит две таблицы, два CTA с выбором Telegram/MAX и три изображения вместе с обложкой.

Публикация ограничена одним case, metadata label/description/proof/thumbnail, новой media attachment и двумя новыми asset-файлами. Статус, slug, даты и остальная metadata case сохраняются; другие посты, очередь, формы, боты, второй сайт и клиентский портал не меняются. Перед применением — независимое exact-head review, после — целевая страница, каталог/главная, sitemap, llms.txt, sales feed и доступность трёх изображений. Private receipts сохраняют границы операции; backups не создаются.
