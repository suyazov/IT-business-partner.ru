Оба домена переключены на WordPress. Владелец отдельно разрешил публикацию после независимого review и проверок, затем отменил создание бэкапов и приказал удалить копии текущего переноса. Это исключение относится только к текущему переносу.

## Nginx

Итоговые два доменных конфига — в `deploy/nginx/`. Сохранены TLS и доменные include; изменены только эти vhost, `nginx -t` и reload успешны. DNS, сертификаты, почта, платёжные сервисы и общие пулы PHP не менялись.

Существующий sy3 include блокировал REST-запросы редактора. Для `/wp-json/wp/v2/users/me` добавлена точная передача WordPress; для коллекции `/wp-json/wp/v2/users` принудительно добавляется `context=edit`, чтобы WordPress проверял capability `list_users`. Без авторизации оба endpoint возвращают 401. Общий include не изменён; XML-RPC и прямой доступ к конфигу остаются закрыты.

## Проверено

HTTPS-проверка на сервере с реальными доменами, SNI и сертификатами через loopback: 64 HTML-страницы, 60 ресурсов, 21 точный редирект, вложенные sitemap, llms.txt и оба feeds по 25 кейсов. Корневой robots.txt разрешает индексацию; WordPress штатно закрывает от неё внутренний поиск.

Браузер: главная sy3 на 1440px, личный сайт на 390px, WebGL, изображения, отсутствие горизонтального переполнения. Редактор главной: 112 валидных блоков. Создание черновика и удаление через авторизованный REST проверены; тестовая запись удалена. Обе админские авторизации и ru_RU проверены. Контрольные данные и доступы не публиковались.

Результат — опубликованная платформа и контент; рост обращений, трафика или продаж ещё не измерен. Временные установочные архивы/выгрузки удаляются под storage lock; receipts, рабочий Git и полезные редакторские изменения сохраняются.
