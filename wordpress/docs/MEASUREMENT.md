WordPress plugin `wordpress/plugin/sy3-measurement.php` с нативной страницей **Настройки → Аналитика и поиск SY3**. Номер счётчика и verification tokens хранятся в WordPress option `sy3_measurement_settings`; пароли и доступ к кабинетам плагину не нужны. Учётные данные в Git не сохраняются. Пустые настройки не подключают сервисы.

Плагин использует Settings API, `options.php`, стандартный nonce из `settings_fields()` и capability `manage_options`. Три независимых поля: номер Метрики, один Yandex verification token и один Google verification token. Произвольных JS/HTML, remote credentials, API-вызовов из PHP, нескольких токенов или импортов из кабинетов нет. Сохранённые значения повторно проверяются перед выводом, лишние ключи не используются. Неверный ввод показывает ошибку и оставляет прежнее проверенное значение; пустое значение явно отключает соответствующий код.

Форматы: counter ID — положительное десятичное число до 15 цифр; Yandex — 16 hex-символов; Google — 20–200 символов из `A–Z a–z 0–9 _ -`. Вставлять нужно только значение `content`, не полный метатег. Если выданное сервисом значение имеет другой формат, не ослаблять проверку наугад: сначала сверить исходный код подтверждения.

Вывод через `wp_head` разрешён только при canonical `home_url=https://sy3.ru/`, реальном `HTTP_HOST=sy3.ru`, HTTPS и environment `production`. На it-business-partner.ru, поддоменах, preview, HTTP, admin, Customizer, REST, AJAX, cron, feed и trackback вывод отсутствует. Forwarded-заголовки самостоятельно не интерпретируются. Метатеги экранированы. JS дополнительно проверяет текущий browser host/protocol, что ограничивает выполнение при копировании или ошибочной выдаче кеша на другой домен.

При валидном counter ID подключается официальный async loader `https://mc.yandex.ru/metrika/tag.js` и стандартная инициализация: `accurateTrackBounce:true`, `trackLinks:true`, `webvisor:false`. Карта кликов, trackHash, запись дочернего iframe, ecommerce и Яндекс Тег Менеджер выключены. Поля заявок, контакты, userID, `params`/`userParams` не передаются; фиксированные конверсии описаны выше. Noscript-пикселя и его запроса нет. Обычные page URL, referrer, cookies и технические данные счётчика остаются частью стандартной работы Метрики; UTM/referrer-атрибуция не вырезается. Контакты и другие персональные сведения нельзя помещать в URL сайта. Возможности, включаемые отдельно в кабинете или другим кодом сайта, этим плагином не проверяются.

Все пустые настройки дают полностью пустой вывод. Одна только активация plugin без значений не создаёт запросов к Метрике и не публикует метатеги. При наличии ранее установленного счётчика нужно исключить двойное подключение до включения этого плагина; автоматически искать и удалять чужой код он не пытается. После изменения значений необходима очистка используемого page cache, иначе посетитель или проверяющий робот может получить прежний HTML.

Установка кода и сохранение tokens **не доказывают** подтверждение собственности в Яндекс Вебмастере/Google Search Console, доступ к существующему счётчику или поступление статистики. После получения значений: независимо проверить публичный HTML, отсутствие вывода на preview, затем завершить подтверждение в кабинетах и проверить реальный сетевой запрос/данные счётчика. До получения значений счётчик не включать. Этот плагин поддерживает HTML-tag verification; Google Domain property требует другого метода, обычно DNS. DNS плагин не меняет. Sitemap `https://sy3.ru/wp-sitemap.xml` нужно добавить в обоих кабинетах после подтверждения прав; установка плагина этого не выполняет.

Проверка исходного PHP: `php -l wordpress/plugin/sy3-measurement.php`. Локальный lint не заменяет проверку WordPress permissions/nonce, рабочего HTML и кабинетов.
