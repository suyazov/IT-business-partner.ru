# WordPress: Сутри и личный сайт Артёма

Опубликовано 22 октября 2026: https://sy3.ru и https://it-business-partner.ru. Обе установки — WordPress 7.1.3 с MariaDB и русской панелью. Исходная версия прошла независимое ревью; подробности — в context.md.

- `theme/` — собственная адаптивная тема, обычный редактор блоков, редактируемые меню.
- `plugin/` — типы «Услуги», «Кейсы», архив проектов, связи материалов, SEO, sitemap-совместимые адреса, `llms.txt`, sales feed и точные редиректы.
- `content/` — исходный пакет: 3 услуги, 25 кейсов из AFFiNE, 23 обложки, 10 статей, страницы и сохранённые материалы прежнего сайта. Последующие услуги и статьи добавляются отдельными пакетами.
- `editorial/` — первая сотня экспертных тем; `search-content/` — 100 SEO-тем и обзор комплексной автоматизации; `longform/` — содержательные расширения исходных материалов; `beget-content/` — дополнительные 100 оригинальных тем. Готовые рукописи перечисляются в manifest, задания без текста не считаются готовыми. Текущий фактический объём указан в `context.md`.
- `plugin/sy3-editorial.php` — две независимые очереди 72/24 часа, общая пауза, проверка утверждённой версии и отдельные публикации. Наличие плагина не включает системный таймер.
- `tools/import-content.php` — импорт через WP-CLI; повторный запуск не перезаписывает вручную изменённый контент.
- `docs/ROLLOUT.md` — границы публикации, перенос адресов, восстановление и проверки.
- `docs/DESIGN.md` — выбранное владельцем направление, самостоятельная графика и режимы анимации.

## Установка в согласованное тестовое окружение

Нужен установленный WordPress с PHP 8.1+, WP-CLI и отдельной базой. На production планируется MariaDB; SQLite используется только для изолированной проверки, без подключения к общему серверу баз.

1. Разместить `theme/` как `wp-content/themes/sy3` и `plugin/` как `wp-content/plugins/sy3-content`.
2. Активировать тему `sy3` и плагин `sy3-content`.
3. Проверить состав импорта:

```bash
SY3_IMPORT_DRY_RUN=1 wp eval-file /exact/source/wordpress/tools/import-content.php --path=/exact/wordpress
```

4. На новой тестовой установке импортировать основной сайт:

```bash
wp eval-file /exact/source/wordpress/tools/import-content.php --path=/exact/wordpress
```

Для отдельной установки личного сайта:

```bash
SY3_SITE_MODE=personal SY3_MAIN_URL=https://sy3.ru wp eval-file /exact/source/wordpress/tools/import-content.php --path=/exact/personal-wordpress
```

Импорт сначала устанавливает режим сайта. Менять роль существующей установки этим скриптом нельзя. Несвязанные записи с теми же адресами вызывают остановку. Заводские страницы WordPress удаляются только на доказанно новой тестовой установке, по их точным ID; скрипт их не удаляет.

При импорте на HTTPS-сайт передавайте `HTTPS=on SERVER_PORT=443`, чтобы встроенные в блоки URL изображений сразу использовали HTTPS.

Обычный повторный импорт сохраняет тексты и редакторские статусы. `SY3_IMPORT_UPDATE=1` обновляет только записи импорта, чьи тексты всё ещё совпадают с сохранённым хешем. Изменённые вручную записи сохраняются, импорт останавливается с указанием конфликта. Автоматическое восстановление ручных изменений не выполняется.

Запуск на production дополнительно блокируется без `SY3_ALLOW_PRODUCTION_IMPORT=1`. Эта переменная — технический предохранитель, а не разрешение владельца на публикацию.

## Работа редактора

- Главная и обычные страницы: «Страницы», редактор блоков.
- Услуги и кейсы: отдельные разделы панели управления; карточки разделов формируются автоматически из опубликованных записей.
- Обложки кейсов импортируются в медиатеку и доступны как обычное изображение записи. Повторный импорт использует существующие вложения по SHA-256 и сохраняет выбранную редактором обложку. Направления кейсов редактируются как стандартная таксономия.
- Статьи: «Записи», рубрики CRM / Интеграции / ИИ / Процессы.
- Меню: «Внешний вид → Меню».
- На главной динамические подборки вставлены блоками shortcode. Редактор меняет тексты страниц и записей; новые опубликованные записи попадают в подборки.
- Публичные обращения идут через Telegram, email и телефон. Формы с неподтверждённой доставкой и аналитические трекеры не добавлены.
- Работа с черновиками, таблицами, схемами и повторным подтверждением после правок описана в `docs/EDITOR.md`.

## Длинные материалы и редакционный контроль

Компиляторы `tools/compile-search-content.py`, `tools/compile-longform.py` и `tools/compile-beget.py` собирают независимые авторские пакеты. В обычном режиме требуется полный набор соответствующей серии; `--ready-only` явно разрешает промежуточный пакет и сохраняет календарные места остальных тем. Для Beget первый каталог содержит все сто заданий, следующие дополняют незавершённые рукописи с неизменной идентичностью темы. `--audit-only` в Beget/longform проверяет материалы без записи canonical.

Готовность требует минимум 10 000 содержательных видимых знаков, практических таблиц, уникальной схемы процесса, первичных источников и самостоятельного текста. SVG и CSV формируются из схемы и первой таблицы, хеши включаются в manifest. Схемы, источники и контакты не увеличивают счётчик основного текста. Автоматический поиск длинных повторов дополняется предметным редакторским ревью; количество знаков не заменяет проверку содержания.

`tools/import-search-content.php` создаёт новые записи черновиками и сохраняет существующие тексты. `tools/refine-longform.php` добавляет проверенные расширения к исходным блокам и сохраняет даты, статусы, обложки, расписание и связи. Оба сначала запускаются с `SY3_IMPORT_DRY_RUN=1`. Дополнительный набор Beget выбирается `SY3_CONTENT_COLLECTION=beget`; частичные импорты требуют явных `SY3_SEARCH_PARTIAL_IMPORT=1` или `SY3_LONGFORM_PARTIAL_IMPORT=1`. Эти флаги не дают production authority.

`tools/audit-longform.php` читает реальное состояние WordPress: объём основного текста, таблицы, схему, обложку и утверждённую версию. `SY3_LONGFORM_REQUIRE_ALL=1` завершает проверку ошибкой, пока все 311 принадлежащих проекту материалов не готовы; промежуточные результаты не объявляются выполнением всей задачи. Полная проверка редактора должна обходить REST с устойчивой сортировкой по ID и проверять уникальность записей между страницами.

## Проверки

```bash
python3 wordpress/tools/smoke.py http://127.0.0.1:8186 http://127.0.0.1:8187
git diff --check
```

После переноса портфолио HTTP smoke охватил 64 HTML-страницы, 60 локальных ресурсов, 21 точный редирект, sitemap и вложенные sitemap, llms.txt и оба sales feeds с одинаковыми 25 кейсами. Каталог с направлениями и обложками проверен в браузере на 1440px, кейс — на 390px. Ранее проверены мобильные меню, 112 корректных блоков главной в редакторе, движение, пауза, `prefers-reduced-motion`, SVG fallback и потеря WebGL-контекста. Это эмуляция мобильного viewport, не тест реального телефона. После ошибочной очистки общих cookies первая проверка закрыта; дальнейшие браузерные действия выполняются только в собственном изолированном контексте и своей вкладке.

Версии локального стенда: WordPress 7.1.3, PHP 8.4.27. Наличие перевода панели `ru_RU` на этом стенде не подтверждено; пользовательские тексты русские. На целевом сервере проверяется доступная поддерживаемая версия WordPress, расширения PHP и локализация до переключения домена.
